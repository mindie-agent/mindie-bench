# mindie-bench 0.4.10: local & remote NPU storage/worktree lifecycle hardening

[中文](mindie-bench-0.4.10.md)

This release completes the Wave 1 storage and worktree lifecycle leak fixes. Temporary workspaces, remote Git worktrees, large container artifacts, and test corpus snapshots created by the harness now have explicit ownership, close ordering, and forced-reclamation paths instead of being skipped on error or after an expired deadline.

- **Tiered-knowledge temporary workspace**: `evaluate_applicability_and_distractors(..., workspace=None)` installs graded corpora and opens three SQLite `Store`s under its own `mindie-tiered-*` directory. All stores now close first (mandatory before unlinking `.sqlite3` files on Windows), and the owned directory is force-removed in `finally` on both success and exception paths. A caller-supplied `workspace` is preserved.
- **Remote NPU worktree and `.bench-home` cache**: `POSTFLIGHT` wraps patch/untracked inspection in `try/finally` and resolves only this slot's exact `<repo>/.git/worktrees/<slot>` admin directory by matching `<admin>/gitdir` to this slot's exact worktree path. Even when the agent created an unexpected `.git` directory, the patch exceeds `32 MiB`, or the untracked inventory exceeds its bound, it removes the `<slot>` worktree, `.bench-home` cache, and that exact admin entry. A shared repository is never swept globally, so a concurrent active slot's metadata is never destroyed. Cleanup errors are returned alongside the primary inspection error, so multi-GB remote directories no longer leak silently.
- **Remote `POSTFLIGHT` timeout arithmetic**: the cleanup script receives a `30s` monotonic budget split into patch/status extraction, a bounded `10s` teardown, and a `5s` final-artifact reserve. `<slot>.final.json` is written atomically before teardown, survives a teardown timeout, and is atomically refreshed with teardown status only when time remains. The outer SSH wait is `50s >= 30s + 15s`, so the caller no longer times out before `.final.json` exists.
- **Remote `<slot>.final.json` artifact**: `RemoteSlot.close()` first persists the local `remote_cleanup.json` through a same-directory temp file plus `flush`, `fsync`, and `os.replace`. Only then does it remove the remote `<slot>.final.json` (about 85 MiB with base64 patches) within a 15-second cleanup grace; an `fsync`/replace failure leaves the remote artifact intact. It also sweeps this user's `<slots_root>/*.final.json` files older than 48 hours when no slot is active.
- **Local worktree cleanup under an expired deadline**: `WorktreeSlot.cleanup()` reserves a `CLEANUP_GRACE_S = 15.0` budget: `10s` for metadata reattach plus `git worktree remove --force`, and `5s` for a pure-Python fallback that removes the owned tree and this slot's exact `self._admin_dir` recorded from its `.git` pointer. Even when the remove sub-budget is already exhausted, the fallback still runs, and sibling entries under `<repo>/.git/worktrees/` are never touched. The continuation executor reserves `patch_capture + CLEANUP_GRACE_S + verifier drain` in its `outer_timeout` up front (default `750s = 600s + 120s + 10s + 15s + 5s`).
- **Bounded cache and test fixture**: the KDA build cache removes its PID-suffixed temporary directory when `copy2`/hashing fails and caps `kda_build_out` at 16 completed entries, refreshing `mtime` on a hit for true LRU. In-flight `.tmp-<pid>` directories are never eviction candidates; a stale `.tmp-<pid>` is reclaimed only when its PID has exited and it is older than one hour, via atomic `.trash-*` rename. The test operators snapshot now lives under an isolated temporary directory and is deleted at process exit, with stale snapshots owned by the current user pruned.

This is an independent release: it does not update the historical product channel, component dependency versions, or frozen benchmark task assets.
