An external-launcher data-parallel rank with no scheduled requests must still participate in synchronization. With a Kimi K3 recurrent-attention model, the idle rank currently advances cached convolution and recurrent state belonging to an earlier request. This corrupts later tokens.

Repair the idle-rank path while preserving ordinary one-token state updates and distributed coordination. Keep the complete upstream module and existing interfaces compatible; do not replace native kernels or disable KDA.

The public reproducer is `python3 test_idle_dp_npu.py`, run from the remote source root on the two assigned NPUs. It creates a tiny, real Kimi K3 KDA+MLA+MoE configuration with dummy weights, DP=2 and TP=1, seeds a stale cache index, and exercises real native NPU kernels and HCCL. Rank 1 calls the real `execute_model` with an empty scheduler output; rank 0 is an ordinary one-token positive control. The harness symmetrically supplies `force_attention=True` to the original dummy-run method so eager mode actually exercises attention. The source's `execute_model` determines all idle-state semantics. This activation is part of the published test contract.

The idle rank must leave both cached state tensors unchanged. The ordinary-token control must update both tensors; unrelated cache rows and cross-rank HCCL must remain correct. The private judge varies cache indices, tokens, and seeded state values. This is an eager module contract, not an ACLGraph, serving, or pretrained-model accuracy benchmark. The current hardware is not 310P, so its override is compatibility surface rather than a separate hardware acceptance claim.
